Follow all standard BPMN 2.0 validation rules when writing the updated XML:

STRUCTURAL RULES:
- MANDATORY COLLABORATION RULE: Every diagram with Pools or Lanes MUST define a <bpmn:collaboration> element containing one or more <bpmn:participant> (Pools) that reference their respective processes (e.g., processRef="Process_ID").
- PLANE TARGET RULE: The root <bpmndi:BPMNPlane>'s bpmnElement attribute MUST point to the <bpmn:collaboration> ID (e.g., bpmnElement="Collaboration_1"), NOT the process ID.
- SAME SYSTEM RULE: Put actors inside the same system in swimlanes within a single pool.
- MANDATORY INCOMING/OUTGOING RULE: Every flow node (startEvent, userTask, serviceTask, exclusiveGateway, parallelGateway, endEvent, etc.) MUST explicitly list its incoming and/or outgoing sequence flows using `<bpmn:incoming>` and `<bpmn:outgoing>` child elements referencing the sequence flow IDs. A Start Event must have `<bpmn:outgoing>`, an End Event must have `<bpmn:incoming>`, and tasks/gateways must have both incoming and outgoing tags corresponding to their flows. Failure to do so will result in "no-disconnected", "no-implicit-start", and "no-implicit-end" validation errors.
- COMPLETE END-TO-END STEPS (NO SHORTCUTS): Never summarize or omit process steps. Every single user action (inputting a field, uploading a document, clicking a submit button) and system action (validating data, querying database, returning error messages, sending emails) must be modeled as individual sequential tasks. Both end-users and developers must understand the full execution path.
- VALIDATION TIMING & ACTION TRIGGERS (CRITICAL): Model when validation happens: Auto Validation (as-you-type) vs. Click-to-Validate button click. Action flows must show the trigger event and actor (e.g. flow name: "Nhấn nút Lưu (Admin)"), and the loop-back error path must describe the exact UI feedback (e.g. flow name: "Trùng tên (Báo lỗi đỏ trên UI)").

- GATES & OUTGOING FLOW LABELS: Do not limit labels to just simple "Yes" or "No". Use descriptive business outcomes or check results directly on sequence flows (e.g., name="Vi phạm", name="Pass", name="Thành công", name="Thất bại", name="Có nhu cầu gia hạn", name="Không có nhu cầu", name="PERSONAL", name="ENTERPRISE").
- Parallel Gateway vs Multi-Type Classifier: When a process splits into multiple parallel configuration flows or independent resource types, use a Parallel Gateway (<bpmn:parallelGateway>) with a plus (+) symbol.
- NO MULTIPLE INCOMING FLOWS ON TASKS/EVENTS (ANTI-FAKE-JOIN RULE): Never connect multiple incoming sequence flows directly to a single Task or End Event. If multiple paths converge, you MUST merge them first using an explicit Join Gateway (Exclusive Gateway <bpmn:exclusiveGateway> if paths are exclusive/conditional, or Parallel Gateway <bpmn:parallelGateway> if paths are concurrent/parallel) before connecting to the target Task/Event. This avoids "fake-join" validation errors.
- LOOP-BACK AND START MERGE RULE (CRITICAL): If a User Task (e.g., "Nhập thông tin") is the target of a validation loop-back (retry flow) and is also preceded by a Start Event, you MUST NOT connect both the Start Event and the loop-back flow directly to the User Task. Instead, insert an Exclusive Gateway (<bpmn:exclusiveGateway> serving as a merge point) immediately BEFORE the User Task. Connect both the Start Event and the loop-back flow to this Merge Gateway, and then connect the Merge Gateway to the User Task via a single sequence flow.

DATA SPECIFICATION RULES (CRITICAL):
- For EVERY User Task: attach a <bpmn:textAnnotation> via <bpmn:association> listing all form fields, with mandatory fields prefixed by (*), data types, and validation rules.
- For EVERY Service Task: attach a <bpmn:textAnnotation> via <bpmn:association> listing operation type, target database/API, field mappings, and constraints.
- LINE BREAKS & BULLET FORMAT IN ANNOTATIONS: You MUST use actual line breaks (carriage returns or &#10;) inside the <bpmn:text> element to format details on separate lines. Always use clear, structured bullet list prefixes (e.g., "1. Field A\n2. Field B" or "+ Rule A\n+ Rule B") to ensure clean, professional legibility. Never output them as a single long line.
- ANNOTATION SIZING LIMITS: The width of the Text Annotation shape in the DI section must scale to fit the longest line, but MUST NOT exceed 250px (maximum 2.5 times the width of a task/step). The height must scale vertically (e.g., 20px per line, minimum 80px) to prevent overflow.
- STANDALONE SPECIAL NOTES: For general process rules, warnings, or global constraints, create a standalone Text Annotation (<bpmn:textAnnotation>) positioned in a dedicated corner of the diagram (e.g., at X=220, Y=30 or X=220, Y=380). This standalone note MUST NOT be referenced by any <bpmn:association> and must have NO connection line pointing to any task or gateway.
- MANDATORY DI EDGE RULE (CRITICAL): Every <bpmn:sequenceFlow>, <bpmn:association>, and <bpmn:messageFlow> MUST have a corresponding <bpmndi:BPMNEdge> in the DI section (with correct waypoints connecting the source element to the target element). If you define any association in the process (e.g., id="Assoc_Input", id="Assoc_Validate", id="Assoc_Save", id="Association_1"), you MUST define a corresponding <bpmndi:BPMNEdge> in the DI section (e.g., id="Assoc_Input_di" bpmnElement="Assoc_Input", id="Assoc_Validate_di" bpmnElement="Assoc_Validate", etc.) with its waypoints, otherwise the diagram triggers the "no-bpmndi" linter error and connection lines will be invisible on the canvas.

If a flow needs to go backwards (loop-back) or cross lanes, route it through empty vertical and horizontal spaces (e.g., the empty channel between stacked lanes, which is usually Y=180 to Y=210 for lanes at Y=120 and Y=270). Use a step-like path with multiple waypoints to route around task boxes. For example, to loop back from a Gateway at (X=520, Y=270) to a Merge Gateway at (X=260, Y=120), route the waypoints as: (520, 270) -> (520, 190) -> (260, 190) -> (260, 120). Never route it directly through the Y-level of other tasks (like Y=120 where the input task is positioned).
